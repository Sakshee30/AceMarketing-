FIXTURE HANDBOOK  /  03
Safety, provenance and unresolved contracts
The files do not enforce the environment
The package contains no production credentials, real customer data, live ad accounts, bank/card details or reachable telephone numbers. Emails end in example.test; recipient and provider identifiers begin SIM_. These conventions are not sufficient protection by themselves: deny external egress, capture all transports, verify an isolated environment identity and refuse production credentials before application execution.
Map before import
The supplied plan establishes scope and target volumes, not every application schema or endpoint. All new datasets are a neutral fixture contract. The repository was not re-read in this generation task. Actual API/table names, field mappings, ID types, enums, role permissions, payload limits and native provider wire shapes remain unresolved. Do not bypass validation, invent a route or disable authentication to make imports pass.

Each tenant has eight synthetic users. The logical personas are owner, administrator, marketing operator, analyst, viewer, approver, support operator and billing operator. Support users are deliberately disabled; billing users are deliberately invited. The first six are active at the account level, subject to tenant status and actual authorization.
Credentials and session lifecycle
users.csv supplies a credential_ref, not a password. The seeding adapter must provision each test identity through the actual authentication path and inject fresh test credentials. For expired or revoked sessions, authenticate first and then exercise a controlled clock/TTL or the real revocation operation. Do not insert forged sessions or commit a universal password.
Tenant and workspace boundaries
authorization_cases.json targets tenant B resources using a tenant A actor across read, update, delete, export, search, download, realtime, AI retrieval, worker dispatch and platform control. Canary strings must be absent from unauthorized output. Tenant-owner permission must not be assumed to authorize platform control.
Core owner, administrator, operator, analyst and approver fixture memberships use the first workspace so positive collaboration/approval stories have a common scope. A viewer and invited billing persona use the second. Tests that need broader access must explicitly grant it using the approved role model.

Expected structure
The event baseline has 10,000 lead-created events, 2,000 qualified-lead events, 1,000 payment events and 200 refund events. Monetary amounts are nonnegative integer minor INR units; the event type determines payment versus refund. Refunds reference the preceding payment. Lead state and event scope are internally consistent.
Two independent source series
Provider daily aggregate impressions/clicks/spend and first-party tracking events are intentionally separate source series. Do not sum them as duplicate representations of one measure or force their counts to match. expected_reconciliation.json reports each series separately. The validator checks each against its own records.
Overlay behavior
mutation_overlays.json contains duplicate lead replay, stale updates, consent revocation during queued work, late event replay and shared-device identity cases. Load only the selected overlay after its baseline and restore the isolated state afterward. “Invalid input rejected” can be the correct test outcome; it is not a broken fixture.

Negative CSV handling
invalid_leads.csv deliberately contains harmless formula-like strings such as =1+1. Use a text editor or explicit text-import mode; do not automatically open it as trusted spreadsheet content. The main catalogue escapes these strings for safe viewing. Malformed email/date, foreign workspace, oversized name and mass-assignment inputs are separated from the valid seed.
Privacy inputs cover consent chronology, export, erasure, derived projections, redaction and a fictional 30-day retention policy. The source plan does not establish a legal retention period. Record actual policy exceptions rather than silently adopting these values.

Ground truth and answer evaluation
The QA corpus contains a golden metrics report, activation policy and support FAQ. Foreign-tenant and adversarial documents exercise access boundaries. Numeric assertions use explicit expected values; source attribution is required for grounded factual answers. Conversion rate 0.1 is the fractional form of 10%. Do not let the evaluation input itself override server-side authorization. The numeric_expected and expected_answer fields are grader data, not model prompt content. Keep the answer key out of retrieval and user messages. A forbidden foreign canary or unauthorized external effect is a failure even when the prose sounds correct.
Lifecycle controls
Model versioning, real inference timeouts, cancellation, promotion, rollback and budgets still require a real model runtime and application harness. These fixtures establish inputs; they do not simulate a trained production model or supply a production checkpoint.

FIXTURE HANDBOOK  /  12
Local commands and Jenkins fixture validation
Extract the complete ZIP, open a terminal in AceMarketing_Dummy_Data_v1 and run the local checker. On Windows use python; on Linux use python3. It requires Python 3 with the standard library only.
python scripts/validate_package.py --root .
The checker validates functional/scale counts and relationships, timestamps and monetary totals, golden arithmetic, source-ID mappings, provider specification inventory, AI split integrity, upload bytes and the package SHA-256 manifest. It emits evidence/fixture_validation.json and a JUnit XML report, then exits nonzero if a check fails.
Generate a fresh functional profile
python scripts/generate_profiles.py --profile functional \
  --run-id qa_ci_001 --out ./generated/qa_ci_001
Generate a fresh scale profile
python scripts/generate_profiles.py --profile scale \
  --run-id qa_scale_001 --out ./generated/qa_scale_001
The backslash line continuations above are for a POSIX shell. On Windows run each command on one line. Use a new empty output directory. Defaults reproduce the selected record distribution with seed 20261002; identical run ID and seed produce identical CSV/NDJSON profile bytes. Compressed events use a fixed gzip header timestamp.
Jenkins integration boundary
scripts/Jenkinsfile.fixture-check is a Linux-agent example for fixture validation only. The agent must already have Python and the extracted package. Its JUnit suite name explicitly says FIXTURE_INTEGRITY_NOT_APPLICATION_TESTS. Do not treat a green fixture job as release approval. An application lane still needs schema mapping, auth, services, native simulator adapters, tests and actual business evidence.

Release discipline
