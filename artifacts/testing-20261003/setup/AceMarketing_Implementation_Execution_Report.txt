3. Changes and verified safeguards
Provider transport
Enforces an explicit HTTPS origin allowlist; rejects URL credentials and cross-origin redirects; bounds redirects, bytes and whole-request/body time. Malformed JSON no longer becomes a successful empty report. HTTP errors retain status and retry metadata without raw provider bodies.
Pagination and recovery
Meta repeated cursors and page-cap truncation fail instead of advancing a checkpoint. A page-two failure is tested against real PostgreSQL, then retried to completion. Valid empty data is distinguished from malformed envelopes. Google Ads and GA4 envelope checks were added.
Regression coverage
25 transport checks, 11 actual connector-orchestrator/database cases with only external fetch simulated, and five full-functional data-layer cases are implemented and included in discovery. They are not all 13 providers’ complete wire-contract qualification.
Existing QA repairs retained
The branch also contains earlier parser, token, AI-stream, event-validation, tenant-workspace visibility, new-production-workspace demo-state, reconciliation and CI executable-path fixes. These were retained and regression-tested; pre-existing persisted records were not globally rewritten.
Workflow and artifact integrity
Preparation is read-only and does not rewrite source. An earlier one-time source-patch attempt failed before testing because of workflow permissions; it was corrected without extending application-test privileges. The final upload retains browser metadata covered by the checksum manifest.
After download, all 45 pre-live checksum entries were present and matched. The application, audit and ML artifacts record the same exact candidate.
